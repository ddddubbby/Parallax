# PROTECTED_REGISTER.md — M30 Cleanup Audit, Pass 0

> **34 protected surfaces found across Decision Log entries** (D-001 … D-093) — the 7 seed items from `AUDIT_METHODOLOGY.md` §2 plus surfaces surfaced by the full walk, including M31/D-087 route and wall protections carried forward by M32/D-088, and M33/D-093 drawer + CI verification floors.

This document is the output of Pass 0 of the M30 whole-repo cleanup audit. It lists every code surface — file, function, column, flag, enum value, route, test helper, script, or name — that the Decision Log **explicitly argued into continued existence**: a session already considered removing, renaming, merging, or simplifying it, and recorded in the "alternatives rejected" column why it must stay. Each surface looks dead, redundant, inconsistent, or over-built to a naive `rg`-for-callers pass — and each one is a settled decision, not an oversight.

**How later passes must use this.** Before any Pass 3 / Pass 4 / Pass 5 candidate is labeled `Delete`, `Merge`, or renamed for "consistency," check it here first. **A match is an automatic `Keep — Protected`, full stop** — cite the D-number, do no further analysis, do not re-litigate. `HIGH` = the entry's rejected-alternative reasoning directly names the removal/rename/merge and rejects it. `REVIEW` = strong "looks-dead-but-isn't" signal that a cleanup pass would plausibly flag, but the Decision Log framing is about design/addition rather than an explicit "we rejected deleting this" — verify against the cited entry before acting, but the default is still Keep.

Every surface below was grep/read-verified to still exist in the current tree (2026-07-09). Two decision *supersessions* that could mislead a reader of the older entries are listed at the end.
